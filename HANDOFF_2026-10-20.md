# Mario Kart 64 Python 3 and Azure handoff — 2026-10-20

## Outcome

The Python 3/Gymnasium simulator ran the real game on Azure using the
Dockerized Mupen64Plus emulator and a privately mounted authorized ROM.
The user asked to stop after this validation and delete the Azure instance
to prevent further resource charges. The feature branch and draft PR remain
the development surface; `master` was not changed or merged.

The reproducible deployment procedure is in [AZURE_DEPLOYMENT.md](AZURE_DEPLOYMENT.md).
It pins `sha-cd23a7c8263da6b641d6fe75d4c39252c69d5b45`, the exact
simulator and trainer images used in live validation. The Ubuntu Docker
installer is in `scripts/install_docker_ubuntu_22_04.sh`. The Azure Compose
file is `compose.azure.yaml`. Images are public and exclude the ROM.

## Actual validation

| Check | Result |
| --- | --- |
| VM and Docker | Ubuntu Server 22.04 x64, `Standard_B2ats_v2`, 1 GiB RAM; Docker Engine 29.9.1 and Compose v5.6.0 ran both images. |
| Game and controls | Luigi Raceway, Moo Moo Farm, and Koopa Troopa Beach returned real 640 × 480 RGB frames. Acceleration and left/right commands advanced changing frames on each course; Luigi screenshots showed steering changing the kart's path. |
| Rewards and HUD | All smoke-test rewards were finite. The progress HUD yielded rising checkpoints: Luigi `18`, Moo Moo Farm `53`, Koopa Troopa Beach `24` during the sampled driving sessions. Early `-1` is unknown progress before the line is visible. |
| Reset and reconnect | Each course passed a second reset and a new trainer connection without hanging. |
| Full episode | Luigi Raceway ran 1,250 steps in 100.4 seconds and ended with Gymnasium `truncated=true` at the registered time limit. Highest checkpoint `249`; total reward `-239.0` because the simple straight-acceleration policy got stuck. No invalid frame or RPC failure occurred. |
| VNC | A loopback-only, view-only VNC server was reached through an SSH tunnel. The RFB 3.8 handshake succeeded; captures showed live Mario Kart frames changing during a driver session. |
| Memory | The 1 GiB VM ran the simulator without an observed Linux OOM kill. Docker images were pulled from GHCR, not built on the VM. |

The smoke script saves `reset.png`, `accelerate.png`, `left.png`, `right.png`,

## Fixes made during live debugging

1. The Ubuntu package placed `mupen64plus` in `/usr/games`, which was absent
   from the container PATH. Commit `b9b44fe` adds `/usr/games` and checks for
   the executable at image build time. Before this fix, the first real reset
   failed with `No such file or directory: 'mupen64plus'`.
2. Mario Kart's Retry action reset the progress HUD. Commit `cd23a7c`
   selects the progress HUD after Retry, waits for it to appear, requires a
   contiguous run of HUD pixels before accepting a checkpoint, and treats
   an absent HUD as unknown progress. Before this fix, a stray border pixel
   caused a false checkpoint near `932` and extreme reward spikes.
3. `trainer/episode_test.py` records a complete episode; it was run with a
   bind mount against the validated trainer image. The deployment guide
   provides the exact command for this pinned image.

Local Python tests passed: 11 tests in `tests/test_protocol.py`,
`tests/test_controller.py`, and `tests/test_mario_kart_hud.py`. CI for
`cd23a7c` passed both the test and image publishing workflows. The GHCR
tags are immutable commit-SHA tags. The VM pulled the two images without a
GitHub token.

## Azure and cost state

The Free Trial subscription had its spending limit enabled. Before
provisioning, the North Central US B2ats v2 SKU was available within quota.
A `$5/month` budget alert was created with 50% and 100% email notifications.
The VM used a 64 GiB Premium SSD P6 disk, a Standard static public IPv4
address, and an NSG that allowed only SSH from the deployment client's IP.
RPC and VNC were not publicly reachable.

The B2ats v2 VM and P6 disk match Azure's published introductory free
allowances while this account remains eligible. The Standard public IPv4
address is separately priced at about `$0.005/hour` and would consume trial
credit. The exact remaining free allowance and credit could not be read from
the CLI. A budget alert is a notification, not a spending cap.

On 2026-10-20, Azure resource group `mk64-simulator-rg` was deleted at the
user's request. The final CLI check returned `false` from:

```bash
az group exists --name mk64-simulator-rg
```

No VM, disk, NIC, NSG, or public IP from this deployment remains. The
subscription-level budget alert can
remain for a later recreation and does not itself run resources.

## Scope and next actions

The three tested courses and a full time-limit episode work. A full lap
under a capable driving policy, race-finish detection, all 16 courses, and
course changes inside one persistent RPC connection were not validated.
The legacy `master` history already contains a tracked ROM; this branch's
new image builds exclude it, but Git history cleanup is a separate decision.
The old BC/SAC scripts still use the previous bridge and were not migrated.
No JEPA or training work was started.

To resume later, check the draft PR and CI, review Azure pricing and free
allowances again, recreate the VM using `AZURE_DEPLOYMENT.md`, privately
transfer an authorized ROM, and run the pinned published images. The
view-only VNC display is available through an SSH tunnel while a trainer
session sends actions. Deallocate or delete resources when done.
